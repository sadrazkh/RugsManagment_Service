# راهنمای خواندن کد — سامانه مدیریت فرش

این سند برای کسی است که کدنویسی بلد نیست ولی می‌خواهد بداند **چه چیزی کجا و چرا** اتفاق می‌افتد. روی هر فایل منبع هم توضیح فارسی (`///` یا `//`) گذاشته شده است.

## شکل کلی برنامه

یک برنامهٔ ASP.NET واحد (`src/RugsManagment.Web`) هم صفحه‌های HTML را می‌سازد و هم API را جواب می‌دهد. صفحه‌ها با Razor (فایل‌های `.cshtml`) روی سرور ساخته می‌شوند و هر جا تعامل زنده لازم است، یک «جزیرهٔ» کوچک Vue داخل همان صفحه سوار می‌شود. سرور جداگانه‌ای برای فرانت وجود ندارد.

- **ورود با کوکی**: بعد از ورود، یک کوکی رمزنگاری‌شده (`rugs.auth`) شناسهٔ کاربر، نقش، کارگاه و «مهر امنیتی» را نگه می‌دارد. توکن جداگانه‌ای صادر نمی‌شود.
- **بازبینی نشست**: `Web/Auth/SecurityStampValidator.cs` در هر درخواست کوکی را با دیتابیس مقایسه می‌کند (با کش ۵ دقیقه‌ای). اگر کاربر غیرفعال شود، نقشش عوض شود، رمزش تغییر کند، کارگاهش غیرفعال شود یا اشتراکش تمام شود، نشست‌های قبلی بسته می‌شوند.
- **محافظت CSRF**: هر فرم POST توکن antiforgery دارد. جزیره‌های Vue همان توکن را از `<meta name="csrf-token">` می‌خوانند و در هدر `X-CSRF-TOKEN` می‌فرستند (`ClientApp/src/lib/api.ts`).

## جریان کلی یک درخواست

```
صفحهٔ Razor + جزیرهٔ Vue  →  کنترلر (Web)  →  سرویس (Application)  →  دیتابیس (Infrastructure)
```

مثال: «تکمیل مرحلهٔ قالیشویی یک فرش»

1. کاربر در صفحهٔ جزئیات فرش، در جزیرهٔ `RugWorkflowPanel.vue` دکمهٔ «تکمیل مرحله» را می‌زند.
2. `api.post('/api/rugs/{شناسه فرش}/steps/{شناسه مرحله}/advance')` با کوکی ورود و هدر `X-CSRF-TOKEN` فرستاده می‌شود.
3. `RugsApiController` شناسهٔ کارگاه را از کوکی کاربر می‌خواند (`User.RequireTenantId()`).
4. `RugManagementService` فرش را فقط از همان کارگاه بارگذاری می‌کند و بررسی می‌کند که انجام‌دهندهٔ انتخابی هم مال همان کارگاه باشد.
5. اگر کاربر نرخی وارد نکرده باشد، نرخ توافقیِ انجام‌دهنده (یا نرخ پیش‌فرض مرحله) اعمال می‌شود.
6. `WorkflowEngine.AdvanceStepAsync` مرحله را Completed و مرحلهٔ بعد را InProgress می‌کند.
7. `SaveChanges` همه‌چیز را (همراه ردیف تاریخچهٔ فعالیت) یک‌جا در PostgreSQL ذخیره می‌کند.
8. پاسخ JSON (`RugDto`) به جزیره برمی‌گردد و صفحه به‌روز می‌شود.

صفحه‌های معمولی (مثل فهرست فرش‌ها) همین مسیر را بدون Vue طی می‌کنند: کنترلر MVC (مثلاً `RugsController`) سرویس را صدا می‌زند و نتیجه را با یک view از `Views/` به HTML تبدیل می‌کند.

## لایه‌ها (پوشهٔ `src/`)

| پوشه | نقش | مثال |
|------|-----|------|
| **Domain** | موجودیت‌ها و قوانین ثابت دامنه | `Rug`, `WorkflowTemplate`, `User` |
| **Application** | منطق کار؛ بدون SQL مستقیم و بدون وابستگی به EF Core | `WorkflowEngine`, `CostCalculationService`, `RugManagementService` |
| **Infrastructure** | EF Core، PostgreSQL، Repositoryها، ذخیرهٔ تصویر | `AppDbContext`, `RugRepository` |
| **Web** | صفحه‌ها، کنترلرها، API جزیره‌ها، ورود و امنیت | `Controllers/`, `Controllers/Api/`, `Views/`, `Auth/`, `Program.cs` |

## مفاهیم مهم

- **Tenant (کارگاه)**: هر مشتری شما یک کارگاه جدا؛ فرش، قالب، انجام‌دهنده و … فقط برای همان کارگاه. شناسهٔ چیزی از کارگاه دیگر همیشه «یافت نشد» برمی‌گرداند.
- **ProcessStepType**: نوع کار (قالیشویی، دارکشی، …) — نوع‌های سیستمی برای همه، به‌علاوهٔ نوع‌های اختصاصی هر کارگاه.
- **WorkflowTemplate**: ترتیب مراحل از پیش تعریف‌شده برای کارگاه.
- **RugWorkflowStep**: نمونهٔ واقعی یک مرحله روی یک فرش مشخص.
- **WorkflowEngine**: تعیین می‌کند کدام مرحله فعال است و هزینه چطور جمع می‌شود.

## فرانت (`src/RugsManagment.Web/ClientApp/src/`)

| مسیر | نقش |
|------|-----|
| `main.ts` | جزیره‌ها را در صفحه پیدا و سوار می‌کند (`<div data-island="...">`) |
| `islands/registry.ts` | فهرست نام جزیره ← فایل کامپوننت |
| `islands/` | خودِ جزیره‌ها (هر کدام یک بخش تعاملی از یک صفحه) |
| `components/` | قطعات مشترک (ورودی مبلغ، ویرایشگر هزینه، …) |
| `lib/api.ts` | ارتباط با سرور + هدر CSRF |
| `lib/ui.ts` | پیام‌های کوتاه (toast) و پنجرهٔ تأیید |
| `styles/app.css` | رنگ‌ها و توکن‌های طراحی (Tailwind) |

خروجی `npm run build` در `wwwroot/dist` قرار می‌گیرد و خودِ برنامهٔ ASP.NET آن را سرو می‌کند.
