# Phase 9 — polish, mobile, help, accessibility (everyone; migration M7 is a SEPARATE package that runs alone)

Read first: `scratchpad\hard-rules.md` (mandatory; scratchpad = `docs/plan2`). Spec sections: K.2/P9 (files + acceptance), H.5 (help and onboarding), H.6 (mobile/tablet), H.7 (accessibility), A.2/A.3 (glossary, Simple mode), H.4 (Jalali inputs), J.3 (deferred hygiene), B.4/B.15 (M7: drop `Rugs.PurchaseCost`, `[RequiresBackup("Rugs")]`), L.3/L.4.
Everything P0–P8 is delivered (reports in `scratchpad\reports\`). The daily user is a non-technical bazaar rug exporter (60+); the goal of this phase is that he can do intake of 10 rugs → bale them → add freight → print, without help, in under 20 minutes, keyboard-only or touch.

## Packages (parallel; disjoint)
### "p9-content" — help, Simple variants, onboarding
Owns: `CA/lib/help.ts` content (per role — Operator never sees money/Business-only steps; a help entry for every new screen: Intake, Shipments/Bales/Pack, Costs, Output, Import, Setup), `Views/Help/Card.cshtml` content (the printable one-page card), the remaining Simple variants of `Views/Rugs/{Index, Details}.cshtml` (the workflow-status hiding already landed in P4b), `islands/platform/HomeCoach.island.vue` steps if the spec lists new ones.
### "p9-ui" — inputs, modals, cleanup, fixes
Owns: Jalali inputs (`JalaliDateField`) replacing the native date inputs in `StepFieldsForm.vue`, `RugWorkflowPanel.vue`, `RugSalePanel.vue`, `SalesReport.vue`, `ProviderStatement.vue`, `Views/Settings/Activity.cshtml`, and the date filters of `Views/Rugs/Index.cshtml` (p9-content owns the rest of that file — put your date-filter markup in a NEW partial `Views/Rugs/_DateFilters.cshtml` and change only the one include line); the RugWorkflowPanel modal on UiShell's focus trap; `bg-white` cleanup (tokens) in `RugForm`, `LabelDesigner`, `CustomFieldsManager`, `WorkflowTemplateEditor`, `RugGallery`, `PwaInstall`; label `v-html` escaping; `GroupDetail.vue` (no `prompt()`, no 100-row cap); `AnalyticsService` set-based; `DatabaseSeeder.cs` honours `Seed:Demo`.
### "p9-a11y" — audit and fix across the new screens
Owns: fixes for axe/Lighthouse issues in files of the new screens (Intake, Shipments/Bales/Pack, Costs, Output, Import, Setup, Home) — but only small attribute/markup/CSS fixes (labels, roles, contrast tokens, focus order, aria-live); anything larger goes to "needs from others". Use axe-core injected from cdnjs into the browser pane (or `npx` under `scratchpad\work\`), never added to the repo. Targets: axe zero serious issues; Lighthouse accessibility ≥ 90 on Home, Intake, Shipment and Costs (run `npx lighthouse` against the running app if Chrome is available; otherwise report axe results and the manual checks); manual check that no action needs dragging (SC 2.5.7); 44 px targets; RTL; dark mode; 375 px no horizontal scroll.

### "p9-m7" — runs ALONE after the three packages above
Owns: migration M7 `DropPurchaseCost` (`[RequiresBackup("Rugs")]`) dropping `Rugs.PurchaseCost`, removal of the `[Obsolete]` `Rug.PurchaseCost` property (and any EF mapping), and every remaining reference (there should be none outside the migration history; M2's Down may still reference the column by SQL — keep M2 untouched, it already ran). Verify up/down/up on a throwaway DB seeded by the demo seeder.
