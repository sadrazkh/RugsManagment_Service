**Plan folder ("scratchpad").** Every brief's `scratchpad\...` means **`docs/plan2/`** in this repo — NOT your own session temp dir. Source of truth: `final-spec.md` + `spec-errata.md` (errata override the spec). Architecture facts: `map.md` (pre-plan code map; later phases changed things — always read the real files).

1. **Ownership.** Edit ONLY files your package owns (your brief lists them; for anything not listed, follow the spec's K.1 shared-file table and K.2 package lists). If another file must change, do NOT edit it — write the exact change under "needs from others" in your report. Other phases may be running in parallel in the same working tree.
2. **Git.** NEVER run git commands that change state (add/commit/push/rm/checkout/reset/stash/restore/merge). The orchestrator commits. Read-only git is fine.
3. **Persian text never goes through the shell** (Git Bash turns it into `?????` in psql/curl). Write Persian only with the Write/Edit tools. Persian test data goes in through the browser pane `fetch` + `JSON.stringify`.
4. **Databases.** NEVER touch `rugs_management` (the owner's real data) — no migrate, no writes, no reads needed. Use throwaway DBs named `rugs_<phase>_<x>` and drop them when done. The orchestrator applies migrations to the real DB after a backup (procedure in `HANDOFF.md`). Never edit a migration that already ran on the real DB (M0–M3; see `HANDOFF.md`).
5. **Builds.** `dotnet build RugsManagment_Service.slnx -p:NuGetAudit=false` (NU1900 comes from an unreachable private feed in the user's global NuGet config — ignore it). CI builds `-c Release -warnaserror`. When other agents run in parallel: "file in use" → wait 30 s and retry; compile errors in files you don't own may be transient. Frontend: `npm run build` (strict vue-tsc) and `npx vitest run` in `src/RugsManagment.Web/ClientApp`.
6. **Tests.** Integration tests use `RUGS_TEST_PG="Host=localhost;Port=5432;Username=postgres;Password=7082"`; reuse `RugsWebFactory` (test auth via `X-Test-Principal`), `TwoTenantFixture`, `AntiforgeryHelper`, `WebSession`. Shared math rows live in `tests/fixtures/math-vectors.json`, consumed by both C# and vitest.
7. **Math.** One rounding rule: half away from zero (`Num.Round` / `MidpointRounding.AwayFromZero`, PostgreSQL `round(numeric)`, `lib/num.ts`). Area per piece = round(L×W, 2), then × qty. decimal/numeric only — never double for money, area or USD. Toman/Rial money and USD declared values are never mixed.
8. **Architecture.** Clean Architecture (no EF in Application); tenant isolation everywhere (cross-tenant → 404 via KeyNotFoundException); every write goes through the Consistency Pass (`IUnitOfWork.SaveChangesAsync`; no `ExecuteUpdate`/raw SQL writes outside the whitelisted ledger repositories); enums append-only with explicit values; new DTO members are trailing optional (never reorder positional records) and every member of a DTO built inside an EF projection is passed explicitly (the SDK does NOT raise CS0854); xmin on user-edited tables with the generated xmin DDL removed by hand and documented in `Migrations/HandEdits/{Name}.md`; new migrations follow B.15 order.
9. **Frontend.** Vue islands registered via the `islands/**/*.island.vue` glob; panels in `panels/*.panel.vue`; Tailwind tokens only (no `bg-white`/hex except print surfaces); icons only from `/icons.svg` (`<icon>` / `AppIcon`); CSP: no inline scripts or handlers, `nonce="@Context.CspNonce()"` on any `<script>`; 44 px targets; RTL; Persian digits for display; numbers through `NumberField`/`lib/num.ts`; Jalali dates through `JalaliDateField`; Persian copy from the spec glossary (A.2) and messages from `Messages.fa.*` / `lib/messages/*`.
10. **Style.** Match surrounding code: Persian XML-doc comments that explain *why*, English identifiers, Persian user-facing strings in natural bazaar Persian.
11. **Report.** Return: files created/modified/deleted; verification commands + results; acceptance bullets pass/fail with evidence; what you could not do and why; "needs from others" (exact edits).
12. **Report file.** Besides returning your report, also write it (same content) to `docs/plan2/reports/<your-agent-label>.md` with the Write tool, so later phases and resumed runs can read it (the orchestrator commits it).
