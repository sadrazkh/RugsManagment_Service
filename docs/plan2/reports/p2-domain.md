### Where I went beyond or tightened the spec
- **Old code that sets `Rug.LengthMeters`/`WidthMeters`** now follows the I.3 legacy rule inside the entity:
  - With no final size, the setter also writes the intake size, so rugs created by the old services stay consistent.
  - With a final size, writing the same value does nothing; a different value throws `DomainConflictException` (409, field `rug.length`/`rug.width`).
- **The new v2 fields on `Rug` have private setters.** Use the methods: `SetIntakeSize`, `SetFinalSize`, `SetFinalSizeSameAsIntake`, `ClearFinalSize`, `SetSerialAndQuantity`, `SetSerial`, `SetQuantity`.
- **Area properties:** `AreaM2`, `TotalAreaM2` and `IntakeAreaM2` are stored generated columns in the DB. In C# the getters compute the same formula from the current sizes, so the value is right even before a save. They never show up in a change diff. `AreaSquareMeters` now returns the rounded `AreaM2` (I.3).
- **Serial range CHECK is stricter than written:** `SerialFrom` and `SerialTo` are both set or both null, and a single serial stores `SerialTo = SerialFrom`. Otherwise "3778" with quantity 50 would pass the check.
- **Leading zeros:** "0123" keeps its zeros for display but counts as the number 123. A digit string too large for `int` is stored as a text serial.
- **Purchase line → cost category FK** uses NO ACTION instead of RESTRICT. Deleting a category in use is still blocked (tested, error 23503), but deleting a whole tenant cascades cleanly.
- **`CostScope` is created now**, although K.2 lists it under P5, because `CostCategory.DefaultScope` needs the type.
- **`LargestRemainder` lives in `Domain/Costing`** as the single implementation of the D.3 split. It returns flags for clamped negative weights and for the all-zero-weights equal split.
- **Old batches** get numbers 1..N in creation order, `SellerKey = ''` and `ReceivedOn = NULL`, so they can't collide on the one-batch-per-seller-per-day key.
- **`Down()`**:
  - writes each rug's purchase-line total back into `PurchaseCost`;
  - restores the original sizes only for rugs whose size hasn't changed since M2, keeping later edits;
  - deletes the `batch` counter;
  - keeps the `_m2_rug_dims_backup` table (only M7 drops it).
- **Rounding count** is recorded with `RAISE NOTICE` and as a comment on the backup table (EF doesn't log notices).
