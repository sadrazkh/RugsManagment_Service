# سامانه مدیریت فرش (Rugs Management)

سیستم چندمستأجری (Multi-tenant) برای مدیریت گردش کار فرش از پذیرش/تولید تا فروش و تسویه با استادکارها.

## معماری

یک اپلیکیشن یکپارچه ASP.NET MVC/Razor که **Vue را به‌صورت «جزیره» (island)** — مانند jQuery — درون viewها استفاده می‌کند. **هیچ سرور جداگانه‌ای برای فرانت در تولید لازم نیست.**

```
src/
  RugsManagment.Domain/          موجودیت‌ها و قوانین دامنه
  RugsManagment.Application/     سرویس‌ها، DTO، موتور گردش کار و محاسبهٔ هزینه
  RugsManagment.Infrastructure/  EF Core + PostgreSQL، Repository، Seed
  RugsManagment.Web/             ← میزبان: MVC + Razor + کنترلرهای /api + جزیره‌های Vue
      ClientApp/                 پروژهٔ Vite (فقط زمان build؛ در تولید اجرا نمی‌شود)
      wwwroot/dist/              خروجی build جزیره‌ها (توسط Razor از manifest خوانده می‌شود)
tests/
  RugsManagment.Tests/           تست واحد (xunit) برای هزینه، گردش کار، اسکیما و تقویم
```

لایهٔ **Application هرگز به EF Core ارجاع نمی‌دهد** — دسترسی داده از پشت interfaceهای Repository می‌گذرد.

- **جزیره‌های Vue:** در هر view کافی است `<div data-island="نام" data-props='{...}'>` بگذارید؛ فایل `ClientApp/src/main.ts` آن را پیدا و mount می‌کند. کلاس `Frontend/ViteAssets.cs` فایل‌های هش‌دار را از `manifest.json` می‌خواند.
- **احراز هویت:** مبتنی بر Cookie (طبیعی برای MVC). نقش‌ها: `SystemAdmin`، `TenantAdmin`، `Operator`. جداسازی کامل مستأجر — دسترسی بین‌کارگاهی ۴۰۴ می‌گیرد نه ۴۰۳، تا وجود رکورد هم فاش نشود.
- **APIها:** با هدر `X-CSRF-TOKEN` محافظت می‌شوند و همیشه به کارگاه کاربر محدودند.
- **موتور هزینه (`ICostCalculationService`):** ثابت، ×طول، ×عرض، ×مساحت، ترکیبی، دستی + تخفیف/اضافه — همه در بک‌اند.
- **موتور گردش کار (`IWorkflowEngine`):** مسیر داینامیک هر فرش، قالب‌های قابل‌ویرایش، حرکت جلو/عقب.
- **نمایش فارسی:** تاریخ شمسی، اعداد فارسی و واحد پول کارگاه (تومان/ریال) در لایهٔ نمایش؛ ذخیره‌سازی همیشه UTC و decimal می‌ماند.
- **حالت تاریک:** با کلاس روی `<html>` و ذخیره در `localStorage`، بدون «فلاش سفید» هنگام بارگذاری.
- **PWA:** نصب‌پذیر روی موبایل/تبلت (`manifest.webmanifest` + `sw.js`) با صف آفلاین برای ثبت مراحل بدون اینترنت.

## پیش‌نیاز

- .NET 10 SDK
- Node.js 22+ (فقط برای build فرانت)
- PostgreSQL (لوکال یا Docker)

## راه‌اندازی

### ۱) دیتابیس

با Docker:

```bash
docker compose up -d
```

یا از PostgreSQL محلی خود استفاده کنید و رشتهٔ اتصال را در
`src/RugsManagment.Web/appsettings.json` (کلید `ConnectionStrings:DefaultConnection`) تنظیم کنید.

### ۲) build فرانت (جزیره‌های Vue)

```bash
cd src/RugsManagment.Web/ClientApp
npm install
npm run build
```

خروجی در `../wwwroot/dist` می‌نشیند. دستور `build` شامل `vue-tsc` است، پس خطای تایپ همین‌جا گرفته می‌شود.

> در حین توسعهٔ فرانت با HMR: `npm run dev` (پورت ۵۱۷۴) و در `appsettings.Development.json`
> کلید `Vite:DevServer` را روی `http://localhost:5174` بگذارید. برای تولید فقط `npm run build` کافی است.

### ۳) اجرای برنامه

```bash
cd src/RugsManagment.Web
dotnet run
```

روی `http://localhost:5231` بالا می‌آید (پروفایل `http` در `Properties/launchSettings.json`).
هنگام استارت، migration و دادهٔ اولیه (ادمین سیستم، کارگاه دمو، قالب‌ها و — روی دیتابیس تازه — چند فرش نمونه) اجرا می‌شود.

> `dotnet run --no-launch-profile` محیط را **Production** می‌گیرد: لاگ JSON، صفحهٔ خطای سفارشی و HSTS.
> مسیر آپلود و کلیدها همچنان به `App_Data/` کنار پروژه می‌افتند (مسیرهای مطلق `/data/...` فقط
> در `Dockerfile` تنظیم می‌شوند)، پس اجرای محلی در این حالت هم کار می‌کند.

## حساب‌های پیش‌فرض

| نقش | ایمیل | رمز |
|-----|--------|-----|
| ادمین سیستم | admin@rugsystem.local | Admin@12345 |
| مدیر کارگاه دمو | demo@rugsystem.local | Demo@12345 |

- **ادمین سیستم** کارگاه (فروشنده) می‌سازد.
- **مدیر کارگاه** فرش‌ها، گردش کار، قیمت‌گذاری، برچسب‌ها، فیلدهای سفارشی، فروش و کاربران کارگاه خود را مدیریت می‌کند.
- **اپراتور** فرش‌ها را پیش می‌برد؛ حذف فرش، مدیریت کاربران و تنظیمات کارگاه در دسترسش نیست.

## قابلیت‌ها

**فرش و گردش کار**
- ثبت/ویرایش فرش، ابعاد متری با محاسبهٔ خودکار مساحت، فیلدهای سفارشی JSONB.
- فهرست در مقیاس: صفحه‌بندی، جستجوی فارسی (یکسان‌سازی «ی/ک» عربی)، فیلتر و مرتب‌سازی — همه در SQL.
- گردش کار داینامیک: قالب‌ها با drag & drop، مسیر هر فرش، حرکت جلو/عقب، مراحل اختیاری.
- کاتالوگ نوع مراحل هر کارگاه + فرم‌های داینامیک هر مرحله (اسکیمای فیلدها در jsonb).
- گروه‌ها/محموله‌ها + عملیات دسته‌ای (پیشبرد، بازگشت، تغییر مسیر و ویرایش گروهی مشخصات).
- **سطل زباله:** حذف فرش نرم است — مراحل، هزینه‌ها و عکس‌ها می‌مانند و هر زمان قابل بازگردانی‌اند.

**مالی**
- موتور قیمت‌گذاری با پیش‌نمایش زندهٔ بک‌اند و تخفیف/اضافه.
- طرف‌های خدمات (استادکارها): نرخ توافقی هر مرحله، صورت‌حساب، ثبت پرداخت و مانده.
- ثبت فروش واقعی (خریدار، تخفیف، دریافتی، مانده)، سود واقعی در برابر هزینهٔ تمام‌شده.
- گزارش فروش با خروجی CSV و نسخهٔ چاپی.

**دیگر**
- گالری عکس هر فرش (بندانگشتی، عکس شاخص، ترتیب کشیدنی).
- طراح برچسب (بصری drag & drop + QR/بارکد + چاپ) و اسکن QR با دوربین.
- داشبورد و گزارش‌ها: فرش بر اساس مرحله، ارزش موجودی، سود، هشدار کهنگی مراحل.
- تاریخچهٔ فعالیت (چه کسی، کِی، چه کاری) با فیلتر بر نوع رویداد.
- تنظیمات کارگاه: واحد پول، لوگو، فیلدهای سفارشی، نوع مراحل.
- بهره‌وری اپراتور: پالت دستور (`Ctrl+K`)، پیشبرد سریع از فهرست، کار آفلاین با صف ارسال.

## امنیت

- **CSP با nonce** — هیچ اسکریپت درون‌خطی بدون nonce اجرا نمی‌شود. هر `<script>` در view باید
  `nonce="@Context.CspNonce()"` داشته باشد و صفت `onclick="…"` مجاز نیست.
- هدرهای `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy` و `frame-ancestors 'none'`.
- محدودیت نرخ روی ورود: ۱۰ تلاش در ۵ دقیقه از هر آی‌پی.
- کنترل هم‌زمانی خوش‌بینانه با `xmin` پستگرس روی فرش و مراحل.
- اعتبارسنجی آپلود با magic byte (نه پسوند فایل).
- `/health` برای مانیتورینگ (شامل بررسی اتصال دیتابیس، بدون احراز هویت و بدون افشای جزئیات).

## تست و CI

```bash
dotnet test tests/RugsManagment.Tests/RugsManagment.Tests.csproj
```

`.github/workflows/ci.yml` روی هر push و PR سه کار را اجرا می‌کند: build بک‌اند با
`-warnaserror` + تست‌ها، تایپ‌چک و build فرانت، و ساخت ایمیج Docker.

## توسعه

- Migration جدید:
  `dotnet ef migrations add Name --project src/RugsManagment.Infrastructure --startup-project src/RugsManagment.Web`
- افزودن جزیرهٔ Vue: کامپوننت را در `ClientApp/src/islands/` بسازید و یک سطر در `registry.ts` اضافه کنید.
- آیکون‌ها از اسپرایت `wwwroot/icons.svg` می‌آیند (نه emoji): در Razor با `<icon name="…">` و در Vue با `AppIcon`.
- راهنمای فارسی ساختار کد: [docs/راهنمای-کد-فارسی.md](docs/راهنمای-کد-فارسی.md)
